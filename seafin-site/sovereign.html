Decision matrix

Cloud Claude or self-hosted? Pick the right one.

Most businesses should stay on Claude. Local LLMs are a specialty answer to a specific problem. Here's the honest decision tree we walk every customer through — before any money changes hands.

Cloud Claude is right when…
  • Anthropic's BAAs and DPAs cover your data classification
  • You want the best frontier capability (Sonnet / Opus class)
  • Workload is bursty or unpredictable
  • You don't have GPU infrastructure or want to avoid managing it
  • Time-to-value matters more than data residency
  • Total monthly API spend is under ~$3,000–$5,000
  • You're using Claude for Small Business or MCP connectors
Self-hosted is right when…
  • Compliance forbids third-party APIs (CMMC, certain FedRAMP, ITAR, classified)
  • Attorney-client privilege, M&A, or absolute-confidentiality data
  • Air-gapped or low-connectivity environments (manufacturing, defense, ships)
  • Sustained high-volume workload — API costs exceed amortized GPU spend
  • Sub-100ms latency required for embedded or edge inference
  • Auditable, deterministic model versioning required by regulation
  • Cloud AI explicitly disallowed by customer contracts or industry rules
Honest default

Start on Claude. Move workloads to local only when one of the right-column conditions is firm. Hybrid — sensitive inference local, general tooling on cloud — is the most common real-world answer.

Honest scope

What open-weight models can't do yet.

If we don't tell you this upfront, someone else will after you've spent the money. Open-weight models are excellent for many use cases — and meaningfully behind frontier cloud models for others.

⚠ Read this before you commit
  • Capability gap. Open-weight models are roughly Claude Haiku-class today, not Sonnet/Opus-class. For deep reasoning, complex agentic workflows, or frontier coding, cloud still wins.
  • Ongoing ops burden. Industry consensus: budget 0.3–0.5 FTE of an infra engineer per self-hosted LLM for GPU failures, driver updates, eval regressions, observability. Teams that underestimate this abandon self-hosting within 12 months.
  • Model updates require redeployment. Unlike cloud where Anthropic ships new Claude versions transparently, you re-evaluate, re-quantize, re-deploy every upgrade.
  • Initial setup is weeks, not minutes. Cloud Claude is live same-day. Self-hosted is 2–4 weeks for production-grade.
  • Tooling ecosystem is shallower. Claude for Small Business ships with QuickBooks, HubSpot, Microsoft 365 connectors. Local stacks need custom MCP servers per integration.
  • TCO rarely beats cloud until volume is sustained and high. Spending under ~$3K/mo on Claude API today? Self-hosting will cost more all-in for 18+ months. We show the math in the Audit.

FAQ

Sovereign-specific questions.

01 Can self-hosted LLMs really replace Claude for our use case? +
For most workloads that fit Claude Haiku — customer support, document classification, basic RAG, structured extraction, drafting from templates — yes, with thoughtful prompt engineering. For deep reasoning, complex multi-step agents, or frontier code generation, open-weight models are meaningfully behind today. The Sovereign Audit gives you a workload-by-workload assessment instead of a blanket yes/no.
02 What if we want hybrid — some local, others on Claude? +
Hybrid is the most common real-world answer. Sensitive workflows (M&A docs, attorney work product, regulated data) run on self-hosted; general productivity (meeting summaries, internal Q&A, marketing copy) stays on Claude. We build the routing layer so users have a single interface and don't think about which model is answering.
03 Do you fine-tune open-weight models on our data? +
When it's the right call. Most workloads do better with RAG (retrieval over your docs) than with fine-tuning, and RAG is dramatically cheaper to maintain. We use LoRA fine-tuning for narrow, stable use cases where prompt engineering and RAG have proven insufficient. The Audit identifies whether your case is fine-tune-worthy or whether RAG is enough.
04 Can we run this without buying GPUs? +
Yes. Lambda Labs, RunPod, CoreWeave, and Modal offer dedicated-tenancy GPU rental with stronger isolation than shared cloud APIs — you still own model weights and control data flow, but you don't capex-buy hardware. Suitable for many "sovereign in spirit, not in physical location" requirements. We lay out the trade-offs in the Audit.
05 How long until production? +
Audit: 1–2 weeks. Build: 2–6 weeks from contract to deployed inference endpoint with RAG layer and observability. Compare to same-day onboarding for Claude — local is meaningfully slower to start but pays off when sovereignty is non-negotiable.
06 What if we want to leave self-hosting and go back to cloud later? +
The orchestration layer we build (RAG, agents, MCP integrations) is model-agnostic. Swapping the inference endpoint from local vLLM back to the Claude API is a configuration change, not a rewrite. No lock-in is one of our explicit deliverables.
